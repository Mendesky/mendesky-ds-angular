元件怎麼選 ​

這篇說明寫畫面時怎麼挑元件：原生 HTML 元素該換成哪個 DS 元件，以及各分組有哪些元件、各自用在哪裡。 開始寫 template 前讀一次。之後不確定該用哪個元件時，回來查表。

先查有沒有現成元件 ​

寫 template 之前，先確認 DS 有沒有現成元件可用。

  1. 要用原生元素（<button>、<input> 這類）時，先看下面的對照表。
  2. 要做選單、浮層、確認彈窗、標籤這類組合時，也先看對照表。表裡列了最常被自己刻的組合。
  3. 表裡沒有的需求，到各分組的元件找用途相符的元件。
  4. 點進元件說明頁，讀「什麼時候用」與注意事項。禁止的做法也寫在那裡。

元件說明會寫明它取代哪些自刻做法，以及自刻會出什麼問題。 例如 app-toast-container 只在 app root 掛一次；自己再建一套 toast 堆疊，兩套會互相遮蓋。

原生元素與自刻組合的對照 ​

原生元素／自刻做法改用怎麼分
<button>app-button、app-icon-btn一般可點擊操作用 app-button；純圖示的操作（工具列、表格操作）用 app-icon-btn
<input>app-input、app-number-input單行文字用 app-input；金額、數量等數字欄位用 app-number-input（有加減鍵與格式化）
<select>app-select、app-autocomplete固定選項用 app-select；要先搜尋、再動態篩選選項時用 app-autocomplete
<textarea>app-textarea備註、描述等多行輸入
自刻 dropdown／menuapp-action-menu右鍵或「更多」按鈕展開的選單
自刻 overlay＋cardapp-modal-shell所有自訂 modal 的容器
自刻確認彈窗app-dialog不可逆操作前的確認，或錯誤提示
自刻 badge／tagapp-label狀態、分類標籤

「怎麼分」一欄摘自各元件說明的用途。細節以元件說明頁為準。

要顯示「有未讀」或未讀數字的徽章，是另一個元件 app-badge，不是 app-label。

例外 ​

下列情況不用套這張對照表：

  • 純 SCSS 或純邏輯的修改。
  • 功能專屬（feature-specific）的元件。

各分組的元件 ​

下面各表的用途欄，取自每個元件說明的「什麼時候用」。點元件名稱可進入說明頁，看屬性與範例。

互動元件 ​

元件什麼時候用
app-button-group2–5 個互斥選項，且視覺需連成一排時用。
app-button任何可點擊操作。禁止原生 <button>。loading=true 時 spinner 取代 icon、底色不變、點擊無效。用投影內容（不給 text，例如選單選項放「標籤＋名稱」）時，裡面的文字顏色寫 color: inherit，否則 ghost／elevated 的滑過、按下文字色套不到（2026-10-02：寫死深色字 → ghost 滑過變深灰底配黑字）。
app-carousel-dot圖片輪播指示、kanban 分頁點。多步驟 wizard 請改用 app-stepper。
app-cell-btn日期/年月選擇器內部的格子按鈕。高密度網格選取場景（年份格、月份格、日期格）。
app-check-chip篩選條件多選、標籤多選、表單內單一 boolean 偏好（如同意條款、Email 通知開關）。禁止用 checkbox 自刻。text 可為使用者自由輸入（inline-add 自訂項目）時無需額外設定——chip 預設就會折行。
app-checkbox單純的勾選框，三態：沒有／全有／部分。「部分」用在「一組裡選了一些」的地方（例：權限清單的分類列）。要「勾選框＋文字」的可點按鈕、只需兩態時，改用 app-check-chip。
app-icon-btn工具列、表格操作、純圖示互動。禁止用 div 包 icon 模擬按鈕。
app-inline-add在 chip 群組 / 清單尾端讓使用者新增「自訂項」。取代 native window.prompt；單行文字輸入不要在 modal 內再疊 dialog。
app-inline-confirm前提依賴型確認（contextualInline）：父層需要使用者在主操作前先勾選「已確認 XXX」。對應 ds-patterns action.precondition-acknowledge.scenarios[0]。
app-radio-chip篩選條件單選、可取消的選項。
app-stepperhorizontal：多步驟 Wizard 進度指示。nav：Modal 左側多層導覽面板。
app-toggle即時生效的開/關設定。
app-upload-dropzone任何需要讓使用者上傳單一檔案的場景。不要自刻拖放區或使用原生 input type="file" 裸露呈現。

表單元件 ​

表單怎麼組、錯誤怎麼提示，見表單與錯誤提示。

元件什麼時候用
app-autocomplete搜尋後動態篩選選項的輸入框。
app-date-picker需要選取民國年、年月、或完整日期（年月日）的場景。
app-field所有表單欄位外層包裝。提供一致的 label 排版。標題只放欄位名稱（中粗 500）；單位（元）、限制（單檔上限 50MB）、提示（可複選）一律放 hint（標題旁淺灰說明），不要寫進 label 文字。跟畫面重複的說明（例如按鈕已列出的選項）直接不寫。
app-input單行文字輸入。禁止原生 <input>。type='password' 時自動顯示 eye toggle。電話/統編等純數字欄位用 inputMode="numeric" sanitize="digits"。
app-number-input金額、數量等數字欄位。有加減鍵與格式化。
app-option-card-group一組互斥的插圖選擇卡（帳務類型 / 客戶設立現況等）。取代散落各處手刻的 .at-grid + onAtGridKeydown 鍵盤 handler。
app-option-card單張可選插圖卡。一般不單獨使用，由 app-option-card-group 組成互斥群組（radiogroup）。hover 揭露純 CSS、無 JS；prefers-reduced-motion 下停用動效。
app-rich-text-editor需要 rich text 輸入的場景（markdown 語法、表格、圖片由 wrapper 擴充）。純文字用 app-textarea；含範本變數用 app-template-editor；含圖片上傳用 app-fee-supplement-editor。
app-select固定選項下拉選擇。禁止原生 <select>。
app-template-editor含範本變數的可編輯文字欄位（如 P5 信件及同意函、P4 合約備註）。與 app-textarea 功能相似但支援 inline badge。
app-textarea備注、描述等多行輸入。禁止原生 <textarea>。
app-year-month-picker需要選取民國年 / 年月 / 期別（1 期 = 2 個月）的場景。值為純字串，透過 ngModel 綁定。單純選年月時優先用此元件，不要自組年月下拉。

浮層元件 ​

不確定該用哪一種浮層時，見浮層怎麼選。 不可逆操作的確認，見確認與破壞性動作。

元件什麼時候用
app-dialog不可逆操作前確認（刪除、封存），或錯誤提示 alert（showCancel:false）。禁止自刻 modal 做確認。title 顏色固定使用 --text/title (#1c1c2e)，禁止 hardcode hex。Warning 只代表「紅色嚴重度」、不等於「刪除動作」：trash 圖示已與 propClass 解耦，僅真正刪除/移除實體才保留預設 Trash-Del，告知型 alert 與非刪除確認（取消封存、復原、成交、匯入）一律 confirmIcon=""。
app-doc-preview預覽已上傳的附件（訪談表檔案、報價附件）。可傳多份，元件自帶前後切換。PDF 與圖片可混在同一份清單，元件依 mimeType 或副檔名自行分派渲染方式。不負責下載或刪除，那些由呼叫端的清單元件處理。
app-drawer-shell所有 Drawer 的容器。提供毛玻璃背景、透明 overlay、進出場動畫（Panel 450ms enter / 300ms exit）、ESC 關閉。禁止各 Drawer 自刻 overlay + panel + animation。
app-keyboard-help集中展示目前畫面可用的鍵盤快速鍵。慣例以 ? 開啟。快速鍵資料由父層傳入，元件不自己蒐集——因為哪些快速鍵有效取決於當前路由與權限。
app-modal-close-btn所有 modal / dialog 的關閉 X 鈕。放進各 modal 自己的 header，關閉決策交 parent。禁止自刻 X button 或散用 app-icon-btn 當關閉鈕。
app-modal-shell所有自訂 Modal 的容器。禁止自刻 overlay + card 組合。
app-process-modal耗時操作的進度顯示（覆蓋整個畫面）。
app-process-toast非同步操作的回饋通知。提供 action 時顯示 undo 按鈕（reversibleToast pattern）。loading 型別搭配 ToastService.show({persist:true}) + update(id, patch) 可做「進行中→完成」單一 toast 原地轉場（如列印產 PDF：訪談表生成中→已開始下載）——update() 僅限這種「同一件事的兩個階段」，不同事件各自一顆、堆疊（2026-07-27 起；先前 HDM 逐欄存檔誤用 update() 取代，已修正）。渲染一律經全域 `app-toast-container`（掛 app root），元件不自建本地 toast stack；唯一例外是 `app-global-api-error-host`（自有 z-index 9999 層，需壓在 doc-preview 之上）。層級規則（2026-08-13 定案）：`app-toast-container` 為 2100，必須壓過 doc-preview 與 template-var-panel 的 2000 層——否則檔案預覽開啟時的操作回饋會被蓋住看不到（先前為 1600，實際被 doc-preview 蓋住）；`app-global-api-error-host` 與 tooltip portal 維持 9999（API 錯誤與游標提示更優先）。duration 由型別決定、呼叫端不自帶：success/loading 3000ms、error 5000ms、有 action 5000ms。容器內 toast 預設 `pointer-events: none`，僅帶 action 者可點（toast 位於卡片右下角，無條件可點會吃掉數秒點擊）。文案長度上限：success/loading 16 全形寬、error 24、有 action 18（`.toast__msg` 的 line-clamp:2 約在 29 全形寬靜默截斷）；插值長度必須有界，守門用 `npm run check:toast-copy`。
app-toast-containerapp root 掛一次就好。任何要顯示 toast 的地方呼叫 ToastService.show() / update()，不要自建本地 toast stack——否則會出現兩套堆疊互相遮蓋。唯一例外是 app-global-api-error-host（自有 9999 層）。
app-tooltipshover 時顯示說明文字。
[appTooltip]替代 app-tooltips component 的 portal 版本。hover/focus 時自動顯示 tooltip，portal 到 body 避免容器裁切。

展示元件 ​

元件什麼時候用
app-action-menu右鍵或 More 按鈕展開的選單清單。選項一律用 app-button variant="ghost"，禁止手刻 <button>/<div>。
app-avatar用戶頭像、個人資料。可點擊（例如右上角打開個人面板）時設 [clickable]="true" 並給 ariaLabel，點擊綁在外層 (click)。
app-badge未讀徽章：疊在按鈕或項目的右上角，表示「有未讀」或「未讀幾則」。目前用在 header 通知鈴與版本更新入口鈕、版本更新視窗的左欄版本列。
app-ctrl-bar頁面或區塊頂部的操作列，左側放篩選/toggle，右側放搜尋/切換。
app-divider區塊分隔。
app-empty-state列表/查詢無資料時顯示。
app-file-list需要呈現已上傳檔案列表並提供操作時。支援「無類型模式」（wizard 報價單）與「有類型模式」（p1 報價依據文件，type 由父層傳入 FileItem.type）。disabled=true 為唯讀，只剩 view。需要 download 或依檔案類型切換動作時不要用這支——它沒有 actions Input；直接用 app-number-list（有 actions Input，NumberListAction 已含 download），客戶文件即如此。
app-footer登入頁與 Shell 共用頁尾。禁止自刻 <footer> 複製文字。
app-icon所有圖示顯示。禁止用 inline style width/height 控制大小，用 size input。
app-kanban-minimapKanban 欄位縮略導覽。
app-label案件狀態、分類標籤。禁止用 div 自刻 badge。Badge 只放文字，不加 icon。放在 ghost 按鈕裡（例如選單選項的統編）用 White（白底灰框），不用 GreyOutline：GreyOutline 是透明底，滑過時灰字疊在深灰底上看不清（2026-10-02 報價案件搜尋框「最近開啟」定案）。報價類型：所客用 GreenOutline、專案用 Purple（新客不標示）；GreenOutline 的字重 600 由這一格提供，呼叫端不要自己補 CSS。KanbanDraft/Opened/DealClosed/Archiving/Archived 五色為 CornflowerBlue 漸層（淺→深對應流程階段），SSOT 來自 Figma 17248:269232（quoting-cases 列表 status pill 專用）。text 綁使用者自由輸入的欄位時必須明示 [wrap]="true"（折行）或 [truncate]="true"+tooltip（省略），不可留預設 nowrap — 預設 nowrap 讓 min-content ＝ 整串寬、chip 在 flex 容器內不可收縮，長值會撐破容器或被祖先 overflow:hidden 靜默裁掉。
app-list-tag清單項目附帶徽章標記。
app-list階層式資料展示。
app-number-list報表數字展示列、檔案列（含檢視／下載／編輯／刪除）。寬度 1024px 以上：label 與 text 放不下截成「…」，只有真的被截斷時滑過／聚焦才顯示全文 tooltip；寬度小於 1024px：改換行完整顯示。手機（小於 768px）按鈕只留圖示，「label＋text＋按鈕」的列改兩行（見下方 note，2026-10-13）。
app-page-skeleton頁面 loading 時的佔位符。
app-po-process採購/流程節點狀態顯示。
app-progress-bar顯示一件分批進行的工作做到哪裡（例：批次授權「處理中 12 / 40」）。只畫比例，不內建文字；「處理中 12 / 40」這類說明由呼叫端排在旁邊。
app-sort-header列表表頭裡可點擊排序的一格。點了發出這欄的 key，由呼叫端決定怎麼排、並把新的排序狀態傳回來；本元件不持有狀態，也不排序資料。

工具 ​

這一組不是元件，是 CSS class 或 directive。用途寫在各自的說明頁。

元件什麼時候用
[appPortalTeleport]元素必須脫離目前 DOM 位置才能正確顯示時用（祖先有 transform、backdrop-filter 或 overflow:hidden）。需要跟著觸發點定位與追蹤捲動時改用 PortalPositioningService。
.ds-collapse內容區塊需要收合／展開動畫時用（例如可展開的卡片段落）。統一用這組 class，不要自己寫 height 動畫。
