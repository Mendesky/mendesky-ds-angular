表格的情境工具列 ​

在富文字編輯器的表格裡，滑鼠移到儲存格時，列的左緣或欄的上緣會浮出一個小把手。點把手會開出只跟那一列或那一欄有關的選單，例如插入、刪除、建立複本。這篇說明什麼時候開這個功能、它怎麼運作。

要讓使用者就地調整表格結構，或想對其他重複的結構做類似的就地操作時，先讀這篇。

先判斷 ​

「情境工具列」指貼在某個區塊邊緣、只跟那個區塊有關的操作入口。它不佔版面，也不改內容。

你的需求做法用什麼
富文字編輯器裡的表格，要讓使用者增刪列與欄開啟表格結構編輯（預設關閉，需要時才開）app-rich-text-editor 的 [tableStructureEditing]="true"
儲存的格式不支援表格連表格工具一起隱藏，快捷鍵與貼上也進不來app-rich-text-editor 的 hiddenTools 傳入 'table'
對其他重複結構（清單項、看板欄）就地施加一組操作套用同一個原則：邊緣把手＋只列相關操作的選單＋範圍高亮下方規則「情境選取工具列」
刪除一列或一欄靠復原，不彈確認 Dialog見確認與破壞性動作
刪除整個表格不放進把手選單，由使用者選取整個表格後刪除—

情境與範例 ​

開啟表格結構編輯 ​

在下面的範例裡，把滑鼠移到表格的儲存格上。列的左緣、欄的上緣會浮出把手。點開選單時，該列或該欄會以外框加淡底標示範圍。

html
<app-rich-text-editor
  [value]="situationDoc"
  placeholder="請輸入客戶背景概況…"
  [readOnly]="readOnly"
  [tableStructureEditing]="true"
  (valueChange)="onSituationChange($event)"
  (composedBlur)="onBlur()">
</app-rich-text-editor>

使用時注意：

  • 觸控裝置沒有 hover。點一下儲存格，把手同樣會浮出。用鍵盤移進儲存格也會。
  • 把手是按鈕，可以用 Tab 聚焦，按 Enter 或 Space 開啟選單。
  • 選單只列跟這一列或這一欄有關的操作。第一列（表頭）的選單不會出現「上方插入列」。
  • 選單開著的時候，把手不會收起來，滑鼠可以安心移到選單上。

選單裡的危險操作 ​

刪除這類危險操作，在選單裡要用顏色加文字一起標示，不能只靠顏色。DS 的選單容器是 app-action-menu，危險項目用 variant="ghost"、color="danger" 的按鈕。

自己實作類似的把手時，先看下方規則的實作要點：把手要掛到 document.body 才不會被裁切；範圍高亮在編輯器管理的儲存格上，必須用 ProseMirror（編輯器底層管理文件內容的框架）的 Decoration 實作，不能直接改 class，否則編輯器重繪時會被抹掉。

規則 ​

情境選取工具列（邊緣把手） interaction.contextual-selection-toolbar

原則：對表格列/欄這類「結構化重複區塊」，在其邊緣 hover（桌面）或 tap/鍵盤進入（觸控）浮出情境把手；點把手得到「只與該列/欄相關」的操作選單（非一次全出）；選單開啟時以整塊外框 + 淡底高亮該列/欄，讓使用者清楚知道操作範圍。把手是就地、非破壞的 affordance——不佔版面、不改內容，收合靠 hover-intent。

什麼時候用：設計「就地對某個重複結構單元（表格列/欄、清單項、看板欄）施加一組情境操作」的互動；尤其在 rich-text / 畫布類元件內。對應：app-rich-text-editor 的 tableStructureEditing、app-rte-table-grip。

情境說明規則
edgeGripReveal雙軌觸發浮出把手：桌面 hover cell → 於列左緣 / 欄上緣浮出把手；觸控 tap 或鍵盤移入 cell（selectionUpdate）→ 同樣浮出（觸控無 hover）
為什麼：Notion 式邊緣把手是「就地、不佔版面」的情境操作入口；雙軌確保觸控裝置（無 hover）也能觸發。portal + detectChanges + display:block 三者是 zone 外命令式掛載浮層的固定坑。
  • 桌面 mousemove + 觸控/鍵盤 selectionUpdate 雙軌，兩者都導向同一 showGripsForCell
  • 收把手用 hover-intent 延遲（~250ms），讓滑鼠來得及移到浮出的把手/選單；把手 mouseenter 取消收起
  • 選單開啟中鎖住把手（不被 hover-intent 收）——否則滑鼠移向浮出選單離開把手 button 時把手被收、選單秒關
  • 把手 portal 到 document.body（避免被 overflow / transform 祖先裁切），命令式 createComponent；zone 外掛載必須 changeDetectorRef.detectChanges() 才 render
  • 把手 host :host{display:block}（不可 display:contents，否則 portal 定位失效）
scopedMenu把手選單只出「與該列/欄相關」的操作，且依情境裁剪：表頭列（第一列）不出「上方插入列」；危險的整表操作不放選單
為什麼：「只出相關操作」降低選單認知負擔；表頭 gate 對齊 Notion；把不可逆的整表刪除排除在易誤觸的浮出選單外，是 action.confirm-destructive 的具體落地。
  • 列把手 / 欄把手各出各自的增刪 + 建立複本 + 清除內容 + 刪除該列/欄
  • 表頭列（第一列）選單不顯示「上方插入列」（已在最上、往上插無意義）
  • 「刪除整個表格」刻意不放選單（危險易誤觸）→ 改由使用者選取整表原生刪除
  • 刪除該列/欄靠 undo 復原、不彈確認 dialog（低成本、可逆）；若操作不可逆才升級為 dialog（見 action.confirm-destructive）
rangeHighlight選單開啟時高亮該列/欄的操作範圍：整塊外框（box-shadow inset 逐邊組合）+ 淡底，內部分隔線維持原色
為什麼：操作前先看清「會影響哪一整塊」是 Notion 式表格編輯的關鍵回饋。Decoration 由 PM 每次 render 重套、重繪抹不掉，是唯一可靠做法。
  • 高亮存在區間 = 選單開啟中；選單關 / 把手收 / 執行指令後即清（choke-point 統一清）
  • PM（ProseMirror）管理的 cell DOM 上做此暫態高亮必須用 ProseMirror Decoration，不可用 classList——classList 會被 wrapper plugin（如 %% autocomplete）在 blur 觸發的 PM 重繪連 nodeview 一起抹掉（2026-07-25 實證：class 加 5 次結束 0、無 remove ＝節點被替換）
  • border-collapse 表格用 box-shadow inset 逐邊組合畫外框（border-color 會被鄰格搶邊而斷裂）；只描外框、欄間分隔線維持灰
  • 切換把手（列選單開→欄選單開）用方向守衛，只有「正在高亮的方向」關閉才清，避免誤清剛套上的另一方向高亮

不要這樣做

  • edgeGripReveal 只掛 mousemove（無 selectionUpdate）→ 觸控裝置永遠看不到把手
  • edgeGripReveal 選單開啟時仍照常 hover-intent 收把手 → 滑鼠移向選單即秒關
  • edgeGripReveal 把手 display:contents 或 zone 外掛載不 detectChanges → 把手掛了卻不顯示 / 定位失效
  • scopedMenu 把整表操作 + 全部列欄操作塞同一選單 → 認知負擔高、危險操作易誤觸
  • scopedMenu 把「刪除整個表格」放進浮出選單 → 不可逆操作放在易誤觸入口
  • rangeHighlight 用 classList / inline style 直接改 PM 管理的 cell DOM → 被 PM 重繪抹掉，真實 app 完全不顯示（unit test 無 wrapper 測不出）
  • rangeHighlight 用 border-color 在 border-collapse 表格描外框 → 被鄰格 border 搶邊而斷裂

無障礙

  • 鍵盤：selectionUpdate 觸發把手 → 鍵盤移入 cell 也能喚出把手（不只 hover）；把手是 <button>（aria-haspopup="menu" + aria-expanded），可 Tab 聚焦、Enter/Space 開選單；選單項為 role="menuitem"
  • 焦點：選單開啟中把手不被收起（focus / 互動不中斷）
  • ARIA：危險操作（刪除列/欄）選單項以顏色 + 文字雙重標示，非僅靠顏色
